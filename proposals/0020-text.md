# Proposal P-0020: text

This proposal decides Cesium's model of text: the type of a string literal, bytes against characters in a `str`, character literals, the encoding, and the built-in `printf`. It carries the design issue #39, with the answers emanspeaks gave there on 2026-11-24 and his correction of the same day on character literals, which replaced the first answer, and the rules of the original design that the reference page "Type System" records. Where the issue leaves a point to the proposal, the point says it is a recommendation. emanspeaks accepts, changes or marks open each numbered point. Nothing in it is decided until he accepts it.

Library names in double quotes (item 5 of #39) are P-0010's (#19); copying and freeing a value that owns memory is #22's and P-0009's; the forms of literals other than strings and characters are #56's.

## Motivation

The reference types a string literal as `str`, and S0 as a NUL-terminated `#u8`; since S0 is a strict subset of Cesium (`s0.subset`), one of them had to change (#39, item 1). Whether `.len` counts bytes or code points, what `'é'` is, and why the built-in `printf`, which takes `{}`, has the name of C's, which the reference's own interop example declares, were all unsettled (items 3, 4 and 7). Stage 1 writes its strings as `#u8` today, and the full language has to say how those agree with `str`.

## Design

Each point names where it comes from: a direction of emanspeaks on #39 (2026-11-24), a rule of the original design as the reference records it ("Rules from the Original Design" of "Type System", and the pages "Lexical Structure" and "Built-in Functions"), or a recommendation.

### String literals

1. A string literal is a static `str`: a pointer and a length, in bytes. Direction (`lex.lit.string.type`).
2. A string literal is stored with a NUL after its last byte, so it also converts implicitly to `#u8`, a pointer to its first byte; this keeps the S0 form valid. Direction (`lex.lit.string.type`, `s0.expr.string`).
3. In S0 a string literal is used only as a `#u8`, and `str` is not in S0. Decided in #9 (`s0.expr.string`, `s0.excluded`).

### Bytes and characters

4. Text is UTF-8. Zig's WTF-8 may be adopted after more discussion, as an implementation detail with the same API. Direction.
5. `.len` of a `str` is its length in bytes, as for any other array, and `s[i]` is a byte, a `u8`. Direction, which did not take the code points and `byte_len` the September 2025 chat proposed.
6. `.strlen` of a `str` gives the number of code points. Direction.
7. The raw bytes of a `str` are reached through `.u8`. Original design.
8. There is no character type: a character is a `u8`. Original design (the reference's "No separate bool or char"); `lex.lit.char`.

### Character literals

9. A character literal is one ASCII character, or an escape sequence, between single quotes, and its value is that character's code, one byte: `'A'` is a `u8`. Direction, the correction of 2026-11-24 (`lex.lit.char`).
10. A non-ASCII character between single quotes, such as `'é'`, is an error; such text is written as a string, `"é"`. Direction, the correction of 2026-11-24, which replaced the answer that took such a literal as its UTF-8 bytes (`lex.lit.char.ascii`).
11. A byte from 128 to 255 is written as a character literal only by an escape, such as a hexadecimal one. Recommendation: the correction leaves it to the proposal; an escape names a byte, not a character, so it does not go against point 10, and C and Zig write such bytes so. The spelling of the escape is open question 1.

### Formatting

12. The built-in `printf` keeps its name, with `{}` placeholders. Direction, which did not take the suggestion to rename it.
13. The placeholders `{}` are filled from the arguments after the format, in order. Original design (the reference's "Built-in Functions").
14. C's `printf` is imported under another name in an `extern` block. Direction; how a function of an `extern` block is renamed is open (open question 6).
15. An interpolated string is text between backquotes, with expressions embedded between `{` and `}`. Original design (`lex.lit.string.interpolated`); not in S0 (`s0.excluded`).

### The reference page

Once the points above are accepted, the reference pages are corrected to match them. These are corrections, not design:

- The C variadics example of "Functions" declares `i32 = printf(str fmt, ...);` in `extern libc = import('c')`: the library becomes `"c"` (P-0010, point 8), the parameter `#u8 fmt`, and the function takes another name (point 14).
- `uword = strlen(str s);  // string length` of "Built-in Functions" is not the `.strlen` of point 6; which free string functions exist is #20's.

## Alternatives

- **`.len` in code points,** with a `byte_len` for bytes, from the September 2025 chat. Not taken by the direction (point 5).
- **A character literal above ASCII as its UTF-8 bytes,** like a short string. emanspeaks's first answer of 2026-11-24, replaced by his correction of the same day (point 10).
- **Renaming the built-in to `print`,** so that C's `printf` keeps its name (the suggestion of #39). Not taken by the direction (point 12).
- **A literal typed as `#u8` only,** as S0 has it. Not taken: the literal is a `str` that converts to `#u8` (points 1 and 2).

## Drawbacks

- `.strlen` counts code points, while C's `strlen` counts bytes; a C programmer reads the name the other way.
- `.strlen` walks the whole string, so it costs time in the length, where `.len` does not.
- Two functions named `printf`, Cesium's and C's, take format strings that look alike and mean different things.
- `'é'` is an error, so a comparison with a non-ASCII character is written against a string.

## Open questions

1. **Escape sequences** of character and string literals: stage 0 takes `\n`, `\t`, `\r`, `\0`, `\\`, `\'` and `\"`; whether a byte escape is `\xHH` (C and Zig) or `\HH` (core SIR's text, P-0006), and whether there is a code point escape for strings, such as `\u{E9}`.
2. **What a `str` owns** (item 2): a literal points at static data and a `str` built by `**` owns memory on the heap; how copying and freeing follow (#22; P-0009, open question 2).
3. **Passing a `str` to a C `char*`:** every `str` keeps a NUL after its bytes, as the original design's "NUL-terminated internally with a tracked length" has it, so that any `str` converts to `#u8`; or only a literal does (point 2), and another `str` is passed through a call that makes a NUL-terminated copy.
4. **Format specifiers** (`{:.6f}` in the first draft), the escaping of `{` and `}` in a format and in an interpolated string, how a user type is formatted, and how an address is printed (#26, item 5).
5. **What `.u8` gives** (point 7), now that `s[i]` is already a byte: a `#u8`, a slice of the bytes, or nothing more than indexing does.
6. **Renaming a function of an `extern` block** (point 14): the reference's `... as name` after the declaration, `alias` (P-0010, point 15), or calling it qualified, `libc.printf` (P-0010, open questions 4 and 5).
7. **Code points:** whether there is a type or an iterator that walks the code points of a `str`, beside `.strlen`.
8. **Wide strings** for the UTF-16 APIs of Windows (item 8): a library function that converts a `str` to a `#u16` buffer, a literal form, or none in the language.
9. **The encoding of a source file** as a whole, and whether a byte order mark is allowed.
